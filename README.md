# HelixFillDNA

Десктопное приложение для Windows, которое конвертирует сырые данные ДНК
(экспорт **FamilyTreeDNA**, **MyHeritage**, **AncestryDNA**, **Атласа**
или готовый **VCF**) в формат
**23andMe**, пригодный для импутации на **Michigan Imputation Server** и 
**TOPMed Imputation Server** для
последующей загрузки в **Генотек**.

> **Новое в 1.3.1: поддержка файлов компании «Атлас».** Они оформлены как
> сырые данные 23andMe, но координаты в них — GRCh38, а не GRCh37, поэтому
> раньше программа принимала их за файл MyHeritage и сверяла позиции не с
> той сборкой. Теперь источник определяется по координатам, а отдельный
> Этап 0 переносит их в GRCh37 и оставляет на диске готовый файл
> «23andMe v3», который можно залить в Генотек как есть. Подробнее —
> ниже в разделе [Файлы Атласа](#файлы-атласа-grch38) и в
> [CHANGELOG.md](CHANGELOG.md).

## Зачем это нужно

FTDNA и Генотек используют разные чипы — наборы позиций в ДНК, которые
они читают. Пересечение между ними — около 49%, а Генотек требует не
меньше 85%, поэтому сырой файл FTDNA он отклоняет напрямую.

Решение состоит из двух шагов: **импутация** (статистическое
восстановление недостающих позиций по референсной панели гаплотипов) и
**сборка итогового файла по трафарету** — по образцу экспорта, который
Генотек уже принимал, с сохранением структуры файла и заменой только
генотипов.

HelixFillDNA автоматизирует весь этот процесс — от подготовки
референсного генома и донорских образцов до финальной сборки файла —
вместо ручного набора команд в Linux/WSL.

## Как это выглядит

![Вкладка «Подготовка» в обычном режиме](docs/prep_simple.png)

Вкладка **«Подготовка»** в обычном режиме: указать нужно только источник
данных и свой файл. Всё остальное — референсную панель, формат вывода,
порог качества, число донорских образцов и сам трафарет — программа
подбирает сама и показывает, что именно выбрала.

![Шаг 1 — подготовка файлов](docs/run_step1.png)

Вкладка **«Запуск»** разбита на три шага. Шаг 1 готовит 23 файла (хромосомы 1-22 и X) для
сервера импутации; по ходу видно, какая хромосома скачивается, сколько
мегабайт уже на диске и с какой скоростью.

![Шаг 2 — импутация на сервере](docs/run_step2.png)

Шаг 2 — единственная ручная часть: загрузка файлов на сервер импутации.
Кнопки открывают сам сервер и папку с готовыми файлами, а параметры,
которые нужно выбрать в форме, вынесены в отдельную рамку — ошибиться в
них дорого.

![Шаг 3 — сборка итогового файла](docs/run_step3.png)

Шаг 3 — вставьте ссылку и пароль из письма сервера, и программа скачает
результаты и соберёт итоговый файл в папку `results` рядом с собой.

## Два режима настроек

- **Обычный** (по умолчанию) — два поля: источник данных и файл. Формат
  вывода выбирается по источнику (FTDNA и AncestryDNA → v3,
  MyHeritage → v5, Атлас → genotek), трафарет
  подставляется из папки `samples`, остальные параметры выставлены на
  разумные значения. Ничего искать и настраивать не нужно.
- **Продвинутый** — все параметры видны и правятся вручную: референсная
  панель (HRC или TOPMed), формат вывода, порог Rsq, нормализация
  multiallelic-сайтов, число донорских образцов, кэши. Значения в нём —
  ровно те, что подобрал обычный режим, так что переключение ничего не
  ломает и показывает, что именно будет использовано.

## Файлы Атласа (GRCh38)

Файл Атласа оформлен ровно как сырые данные 23andMe: одна `#`-строка с
названиями колонок, дальше `rsid / chromosome / position / genotype` через
табуляцию, хромосомы как `X/Y/MT`, гаплоидные вызовы одной буквой.
Отличие ровно одно, и оно принципиальное: **координаты в GRCh38**, а не в
GRCh37, на который рассчитаны трафареты, референс HRC и доноры.

Поэтому для источника «Атлас» программа делает дополнительный **Этап 0**:
переносит координаты GRCh38 → GRCh37 по официальному chain-файлу UCSC
(`hg38ToHg19.over.chain.gz`, скачивается автоматически, десятки МБ) и
пишет рядом с остальными файлами запуска
`<имя>_grch37_23andme_v3.txt`. Дальше пайплайн работает с этим файлом, и
Атлас для него неотличим от любого другого чипа.

Промежуточный файл — самостоятельный результат: это валидные «сырые данные
23andMe v3» в GRCh37, их можно проверить глазами и залить в Генотек как
есть, не дожидаясь импутации.

Какой трафарет выбирать (измерено на реальном файле Атласа, 582 151
маркер — доля позиций трафарета, которые чип покрывает напрямую):

| Трафарет | Покрытие чипом Атласа |
|---|---|
| `template_genotek.txt` | **90,6 %** (563 375 из 621 566) |
| `template_v5.txt` | 82,7 % (532 055 из 643 161) |
| `template_v3.txt` | 18,7 % (179 909 из 959 674) |

То есть Атлас — современный чип семейства Illumina GSA, как у Генотека,
Genera и MyHeritage: с трафаретом Генотека он совпадает почти полностью, а
с v3 (чип 23andMe 2010-х) — почти нигде. Обычный режим подставляет
`genotek` сам.

## Где что лежит

Рядом с установленной программой создаются три папки:

| Папка | Что внутри |
|---|---|
| `samples/` | Трафареты `template_v3.txt` и `template_v5.txt` — входят в установщик, подставляются автоматически по выбранному источнику |
| `results/` | Итоговые файлы всех запусков, с названием запуска в имени |
| `output/runs/<название>/` | Рабочие файлы конкретного запуска: промежуточные VCF, лог, 23 файла (1-22 + X) для загрузки на сервер |

Донорские образцы 1000 Genomes и референсный геном скачиваются один раз
в общие для всех запусков папки `donors/` и `reference/`.

## Проверка файла перед запуском

Перед тем как начать скачивать гигабайты и вставать в очередь на сервер
импутации, программа за несколько секунд читает ваш файл и показывает
отчёт: сколько маркеров и какой у чипа call rate (общий и по каждой
хромосоме), аутосомная гетерозиготность, пол по X и по Y и сходятся ли
они между собой, есть ли вообще Y и MT (то есть будут ли гаплогруппы),
дубли и порядок позиций, сборка генома. Ничего при этом не скачивается.

Там же — рекомендация референсной панели, если доноры уже были скачаны
хотя бы раз. Считается она по составу вашего чипа: доля маркеров,
редких в европейской популяции 1000 Genomes, и доля позиций, которых в
1000 Genomes нет вовсе. Тяжёлый редкий хвост — довод за TopMed, у
которого глубже редкая часть; умеренный — за HRC, который быстрее и не
требует переноса координат между сборками генома. Панель предвыбрана по
рекомендации, но переключается вручную: программа не меняет её молча,
иначе потом невозможно понять, почему два запуска разошлись.

Отчёт можно выключить галочкой в продвинутых настройках. В CLI это
флаги `--preflight` и `--preflight-only`.

## Если файл не приняли из-за заполняемости

Заказчику обычно важен процент заполненных строк в итоговом файле, а
порог качества импутации (Rsq) прямо на него влияет: чем выше порог, тем
надёжнее каждый генотип и тем меньше строк проходит фильтр.

В продвинутых настройках можно задать цель — например «не меньше 92 %».
Тогда на Шаге 3 программа возьмёт уже скачанные результаты сервера,
построит зависимость заполняемости от порога и подберёт **самый высокий**
порог, при котором цель достигнута. Заново отправлять задание на сервер
не нужно: пересчёт занимает секунды.

В лог при этом честно пишется, чем за это заплачено: сколько позиций
прошло с качеством ниже стандартного 0,30 и какая медиана качества у
использованных. Ниже 0,10 порог не опускается ни при какой цели — там
генотип уже почти не отличим от угадывания. Если цель недостижима,
программа так и скажет, а не подгонит цифру.

## Формат вывода и трафарет «genotek»

Форматов вывода три. `v3` и `v5` — оформление настоящих экспортов
23andMe (различаются набором позиций и переносами строк). Третий,
`genotek`, — трафарет, собранный из позиций реальных файлов Генотека:
621 566 строк (аутосомы и X).

Он нужен вот зачем. Сравнение вашего файла с родными данными Генотека
(поиск родственников, общие сегменты) идёт по пересечению наборов
позиций. И тут оказывается, что чип Генотека покрывается нашими
трафаретами очень по-разному:

| Трафарет | покрывает чип Генотека |
|---|---|
| v3 | 30,7 % |
| v5 | 91,1 % |
| genotek | **98,5 %** |

Заполняемость при этом не страдает: доля позиций, которые вообще есть в
1000 Genomes (то есть которые импутация может закрыть), у нового
трафарета 96,8 % — как и у v5.

В трафарете нет ни Y-хромосомы, ни митохондрии. Y нет и у самого чипа
Генотека (а в итоговом файле она в любом случае очищается). Митохондрию
пришлось исключить по другой причине: Генотек записывает её координаты в
системе hg19/Yoruba, а 23andMe и все потребительские чипы — в rCRS.
Разница в 1–2 позиции, зависящая от участка, и из 842 общих маркеров
координаты совпали всего у 13. Ни один источник в эти строки не попал
бы, и блок стоял бы вечно пустым.

Выбирается он в «Продвинутых настройках», в списке «Формат вывода»;
трафарет из папки `samples/` подставляется автоматически.

Одно честное предупреждение: примет ли импортёр Генотека файл с таким
набором позиций — заранее неизвестно. По оформлению это экспорт 23andMe
v5 (шапка, CRLF, колонки), но набор маркеров ему незнаком, и если версию
определяют по маркерам, а не по шапке, файл могут отвергнуть. Если так —
вернитесь к обычному v5.

## Y-хромосома в итоговом файле

Y-хромосома не импутируется: на сервер уходят только хромосомы 1–22 и X.
В итоговый файл она могла попасть единственным путём — прямыми
измерениями чипа, и новые экспорты MyHeritage их содержат.

Начиная с 1.3.0 позиции Y в итоговом файле всегда остаются пустыми
(`--`). Сами строки при этом никуда не деваются: файл построчно
повторяет трафарет, иначе он перестал бы соответствовать формату
23andMe.

Учтите две вещи. Заполняемость итогового файла из-за этого ниже ровно на
долю Y в трафарете: 0,18 % для формата v3 и 0,52 % для v5. И если образец
мужской, то это были настоящие измерения — Y-гаплогруппу теперь можно
определить только по исходному файлу, не по итоговому. Митохондриальная
ДНК и X-хромосома не затронуты.

## Журнал запусков

Рядом с программой копится `runs_metrics.csv` — по строке на запуск:
метрики исходника, состав чипа, панель, порог Rsq и итоговая
заполняемость. Последняя колонка, `verdict`, пустая — её заполняете вы,
когда приходит ответ приёмки. Через десяток запусков по этому файлу
видно, какая заполняемость реально проходит и при каком составе чипа
какая панель себя оправдывает. Файл открывается в Excel.

## Обновления

При запуске программа проверяет, не появилось ли новой версии на GitHub.
Если появилась — покажет номер версии и список изменений; можно открыть
страницу загрузки, пропустить эту версию или совсем отключить проверку
галочкой «Больше не напоминать». Кнопка «⭯ Проверить обновления» внизу
окна спрашивает вручную в любой момент. Программа ничего не скачивает и
не устанавливает сама — только открывает страницу релиза в браузере.

## Если скачивание результатов встало или файл «занят другим процессом»

Скачивание архивов с сервера импутации идёт по одному файлу за раз. Если
в панели видно два «качающихся» архива сразу — значит, второй пишет
чужой процесс: `curl.exe`, оставшийся от предыдущего запуска. До версии
1.3.0 он переживал закрытие окна и продолжал медленно тянуть тот же
файл; следующий запуск натыкался на занятый файл и падал с
`[WinError 32]`.

Начиная с 1.3.0 программа снимает свои закачки сама — и по кнопке
«⏹ Остановить скачивание результатов», и при выходе. Если сообщение о
занятом файле всё же появилось (программу закрыли через Диспетчер задач
или она аварийно завершилась), снимите все процессы `curl.exe`:
Ctrl+Shift+Esc → вкладка «Подробности» → `curl.exe` → «Снять задачу» —
и нажмите «Скачать результаты» ещё раз. Уже скачанное не потеряется:
файлы докачиваются с места обрыва.

Медленная закачка тоже больше не длится вечно: если скорость держится
ниже 20 КБ/с целую минуту, соединение обрывается и переподключается.

## Если пароль не подошёл ко всем архивам сразу

Пароль приходит своим письмом на каждое задание сервера импутации и к
архивам другого задания не подходит. Пароль с опечаткой не подойдёт к
одному архиву; пароль, не подошедший ни к одному из 23, — это почти
всегда пароль от другого задания.

Программа теперь запоминает, от какого задания какие архивы скачаны
(`download_manifest.json` в папке запуска), и перекачивает чужие сама.
Если файлы попали в папку мимо программы — удалите архивы из
`output/runs/<название>/rerun_results/` и скачайте заново, проверив, что
пароль и curl-команда взяты из одного и того же письма.

## Если скачивание падает с ошибкой сертификатов

Симптом — сообщение про хранилище корневых сертификатов Windows, обычно
с текстом `not enough data: cadata does not contain a certificate`.
Интернет и роутер тут ни при чём: соединение даже не открывается, всё
падает раньше, на подготовке защищённого канала. Так выглядит
повреждённое хранилище корневых сертификатов Windows — чаще всего это
последствие антивируса с проверкой HTTPS (Kaspersky, ESET), VPN-клиента
или корпоративной групповой политики.

Начиная с версии 1.3.0 программа обходит это сама, если рядом есть
`bin/cacert.pem` или пакет `certifi`. Если обойти не удалось, починить
хранилище можно так — PowerShell **от администратора**:

```powershell
certutil -generateSSTFromWU %TEMP%\roots.sst
certutil -addstore -f Root %TEMP%\roots.sst
```

Проверить результат: `certutil -verifystore -v Root` — смотрите, на какой
записи вывод обрывается или ругается. Стоит также заглянуть в
`HKLM\SOFTWARE\Policies\Microsoft\SystemCertificates\Root\Certificates`
(сертификаты, навязанные политикой) и временно отключить в антивирусе
проверку HTTPS.

Кнопка «🌐 Диагностика сети» на вкладке «Подготовка» показывает состояние
хранилища одной строкой.

## Системные требования

- Windows 10 или новее (64-бит)
- Свободное место на диске: **не меньше 20 ГБ**. Из них ~3 ГБ —
  референсный геном, остальное — донорские образцы 1000 Genomes и
  временные файлы. В обычном режиме включено хранение сырых хромосом
  (оно экономит трафик при повторных запусках), и это добавляет ещё
  13–20 ГБ; если места мало, снимите эту галочку в продвинутом режиме
- Интернет-соединение (загрузка референсного генома, донорских
  образцов 1000 Genomes, обращение к серверу импутации)
- Для запуска **из исходников** — Python 3.x и зависимости проекта
  (см. ниже)

## Установка

### Вариант 1 — готовый установщик (рекомендуется)

1. Откройте раздел [Releases](https://github.com/Kirten-Po/HelixFillDNA/releases)
   репозитория.
2. Скачайте последний `HelixFillDNA-Setup-X.Y.Z.exe`.
3. Запустите установщик — права администратора **не требуются**
   (устанавливается для текущего пользователя).
4. Выберите язык мастера установки (RU/EN) и, при желании, создание
   ярлыка на рабочем столе.
5. После завершения приложение появится в меню «Пуск» и в разделе
   «Установка и удаление программ» — его можно удалить стандартным
   способом Windows.

### Предупреждение Windows при запуске установщика

Установщик **не подписан цифровым сертификатом**, поэтому Windows может
показать одно из двух предупреждений. Это ожидаемо и не означает, что с
файлом что-то не так.

**«Система Windows защитила ваш компьютер» (SmartScreen).** Нажмите
«Подробнее» → «Выполнить в любом случае». Предупреждение появляется у
любой новой программы, которую скачало мало людей: SmartScreen оценивает
не содержимое файла, а его «репутацию» — сколько раз он уже был безопасно
запущен на других компьютерах.

**«Политика управления приложениями заблокировала этот файл».** Это
Smart App Control (умное управление приложениями) — он блокирует
неподписанные программы целиком, без возможности «выполнить всё равно».
Проверить, включён ли он:

```powershell
reg query "HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy" /v VerifiedAndReputablePolicyState
```

`0x0` — выключен, `0x1` — включён, `0x2` — режим оценки.

Если он включён, выбор такой:

* **Собрать программу из исходников** (см. вариант 2 ниже) — собранное
  вами локально Smart App Control не блокирует. Это рекомендуемый путь.
* Отключить Smart App Control в параметрах безопасности Windows.
  **Учтите: включить его обратно можно только переустановкой Windows** —
  Microsoft сделала это односторонним переключателем. Ради одной
  программы такую цену платить не стоит.

Проверить, что скачанный файл не подменён по дороге, можно и без подписи —
сверьте контрольную сумму файла с указанной на странице релиза:

```powershell
Get-FileHash HelixFillDNA-Setup-X.Y.Z.exe -Algorithm SHA256
```

> Почему установщик не подписан: сертификат для подписи кода стоит денег и
> требует проверки личности удостоверяющим центром. Для бесплатного
> проекта одного разработчика это пока не окупается. Исходный код открыт —
> любой желающий может прочитать его и собрать программу сам.

## Быстрый старт (CLI)

Приложение можно использовать и без графического интерфейса:

```bash
python main.py --csv ftdna.csv --template samples/template_v3.txt \
               --source ftdna --panel hrc --format v3 \
               --run-name ivanov --bin-dir bin
```

Обязательны только `--csv` (ваш файл) и `--template` (трафарет).
Полезные флаги: `--auto-detect-source` (определить источник по самому
файлу), `--preflight` (отчёт о состоянии исходника перед запуском),
`--preflight-only` (только отчёт, без запуска пайплайна — код возврата 1,
если есть серьёзные замечания), `--rsq-threshold` (порог качества, по
умолчанию 0.30), `--normalize`, `--raw-chromosome-cache`, `--donors-dir`,
`--output-dir`. Полный список — `python main.py --help`.

## Как это работает «под капотом»

Коротко, по мотивам полного гайда (`Гайд_по_конвертации.docx`):

1. **Референсный геном** (GRCh37/human_g1k_v37) скачивается и
   индексируется один раз — он нужен, чтобы определить правильную
   ориентацию аллелей в каждой позиции.
2. Сырой файл источника чистится и превращается в отсортированный,
   проиндексированный **VCF**.
3. Сервер импутации требует не меньше 5 образцов в задании. Если своих
   тестов меньше, недостающие берутся из открытого проекта
   **1000 Genomes** (европейская популяция), обрезаются по позициям
   вашего чипа и объединяются с вашим VCF в общее задание.
4. Задание загружается на **Michigan Imputation Server** (панель
   HRC r1.1, GRCh37) — там недостающие позиции статистически
   восстанавливаются по референсной панели гаплотипов. Отправляются
   хромосомы 1-22 и X: сервер сам делит X на псевдоаутосомные регионы
   (PAR1, PAR2) и основную часть (nonPAR) и импутирует их независимо.
   Пол образца определяется по гетерозиготности nonPAR X — у мужчин там
   одна копия хромосомы, и записывать её нужно гаплоидно, иначе сервер
   отвергнет задание. Y и MT не импутируются: их нет ни в одной
   поддерживаемой референсной панели, и в итоговый файл они попадают
   только прямыми измерениями чипа (если есть в исходном файле).
5. Итоговый файл собирается по «трафарету» — реальному экспорту
   23andMe (формата V3 или V5), который Генотек уже принимал: структура
   файла сохраняется один в один, а генотипы заполняются из
   импутированных данных, при этом ваши собственные измерения (там, где
   они есть) имеют приоритет как более точные. Искать трафарет самому не
   нужно — оба формата входят в установщик и лежат в папке `samples`.
6. Готовый файл в формате 23andMe появляется в папке `results` и готов к
   загрузке в Генотек.

Полная пошаговая инструкция — включая ручной прогон без приложения,
через WSL/Ubuntu и `bcftools` — доступна в `Гайд_по_конвертации.docx`.
