# HelixFillDNA

Десктопное приложение для Windows, которое конвертирует сырые данные ДНК
(экспорт **FamilyTreeDNA**, **MyHeritage**, **AncestryDNA** или готовый
**VCF**) в формат
**23andMe**, пригодный для импутации на **Michigan Imputation Server** и 
**TOPMed Imputation Server** для
последующей загрузки в **Генотек**.

## Зачем это нужно

FTDNA и Генотек используют разные чипы — наборы позиций в ДНК, которые
они читают. Пересечение между ними — около 49%, а Генотек требует не
меньше 85%, поэтому сырой файл FTDNA он отклоняет напрямую.

Решение состоит из двух шагов: **импутация** (статистическое
восстановление недостающих позиций по референсной панели гаплотипов) и
**сборка итогового файла по трафарету** — по образцу экспорта, который
Генотек уже принимал, с сохранением структуры файла и заменой только
генотипов.

HelixFillDNA автоматизирует весь этот процесс — от подготовки
референсного генома и донорских образцов до финальной сборки файла —
вместо ручного набора команд в Linux/WSL.

## Как это выглядит

![Вкладка «Подготовка» в обычном режиме](docs/prep_simple.png)

Вкладка **«Подготовка»** в обычном режиме: указать нужно только источник
данных и свой файл. Всё остальное — референсную панель, формат вывода,
порог качества, число донорских образцов и сам трафарет — программа
подбирает сама и показывает, что именно выбрала.

![Шаг 1 — подготовка файлов](docs/run_step1.png)

Вкладка **«Запуск»** разбита на три шага. Шаг 1 готовит 22 файла для
сервера импутации; по ходу видно, какая хромосома скачивается, сколько
мегабайт уже на диске и с какой скоростью.

![Шаг 2 — импутация на сервере](docs/run_step2.png)

Шаг 2 — единственная ручная часть: загрузка файлов на сервер импутации.
Кнопки открывают сам сервер и папку с готовыми файлами, а параметры,
которые нужно выбрать в форме, вынесены в отдельную рамку — ошибиться в
них дорого.

![Шаг 3 — сборка итогового файла](docs/run_step3.png)

Шаг 3 — вставьте ссылку и пароль из письма сервера, и программа скачает
результаты и соберёт итоговый файл в папку `results` рядом с собой.

## Два режима настроек

- **Обычный** (по умолчанию) — два поля: источник данных и файл. Формат
  вывода выбирается по источнику (FTDNA и AncestryDNA → v3,
  MyHeritage → v5), трафарет
  подставляется из папки `samples`, остальные параметры выставлены на
  разумные значения. Ничего искать и настраивать не нужно.
- **Продвинутый** — все параметры видны и правятся вручную: референсная
  панель (HRC или TOPMed), формат вывода, порог Rsq, нормализация
  multiallelic-сайтов, число донорских образцов, кэши. Значения в нём —
  ровно те, что подобрал обычный режим, так что переключение ничего не
  ломает и показывает, что именно будет использовано.

## Где что лежит

Рядом с установленной программой создаются три папки:

| Папка | Что внутри |
|---|---|
| `samples/` | Трафареты `template_v3.txt` и `template_v5.txt` — входят в установщик, подставляются автоматически по выбранному источнику |
| `results/` | Итоговые файлы всех запусков, с названием запуска в имени |
| `output/runs/<название>/` | Рабочие файлы конкретного запуска: промежуточные VCF, лог, 22 файла для загрузки на сервер |

Донорские образцы 1000 Genomes и референсный геном скачиваются один раз
в общие для всех запусков папки `donors/` и `reference/`.

## Системные требования

- Windows 10 или новее (64-бит)
- Свободное место на диске: **не меньше 20 ГБ**. Из них ~3 ГБ —
  референсный геном, остальное — донорские образцы 1000 Genomes и
  временные файлы. В обычном режиме включено хранение сырых хромосом
  (оно экономит трафик при повторных запусках), и это добавляет ещё
  13–20 ГБ; если места мало, снимите эту галочку в продвинутом режиме
- Интернет-соединение (загрузка референсного генома, донорских
  образцов 1000 Genomes, обращение к серверу импутации)
- Для запуска **из исходников** — Python 3.x и зависимости проекта
  (см. ниже)

## Установка

### Вариант 1 — готовый установщик (рекомендуется)

1. Откройте раздел [Releases](https://github.com/Kirten-Po/HelixFillDNA/releases)
   репозитория.
2. Скачайте последний `HelixFillDNA-Setup-X.Y.Z.exe`.
3. Запустите установщик — права администратора **не требуются**
   (устанавливается для текущего пользователя).
4. Выберите язык мастера установки (RU/EN) и, при желании, создание
   ярлыка на рабочем столе.
5. После завершения приложение появится в меню «Пуск» и в разделе
   «Установка и удаление программ» — его можно удалить стандартным
   способом Windows.

### Предупреждение Windows при запуске установщика

Установщик **не подписан цифровым сертификатом**, поэтому Windows может
показать одно из двух предупреждений. Это ожидаемо и не означает, что с
файлом что-то не так.

**«Система Windows защитила ваш компьютер» (SmartScreen).** Нажмите
«Подробнее» → «Выполнить в любом случае». Предупреждение появляется у
любой новой программы, которую скачало мало людей: SmartScreen оценивает
не содержимое файла, а его «репутацию» — сколько раз он уже был безопасно
запущен на других компьютерах.

**«Политика управления приложениями заблокировала этот файл».** Это
Smart App Control (умное управление приложениями) — он блокирует
неподписанные программы целиком, без возможности «выполнить всё равно».
Проверить, включён ли он:

```powershell
reg query "HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy" /v VerifiedAndReputablePolicyState
```

`0x0` — выключен, `0x1` — включён, `0x2` — режим оценки.

Если он включён, выбор такой:

* **Собрать программу из исходников** (см. вариант 2 ниже) — собранное
  вами локально Smart App Control не блокирует. Это рекомендуемый путь.
* Отключить Smart App Control в параметрах безопасности Windows.
  **Учтите: включить его обратно можно только переустановкой Windows** —
  Microsoft сделала это односторонним переключателем. Ради одной
  программы такую цену платить не стоит.

Проверить, что скачанный файл не подменён по дороге, можно и без подписи —
сверьте контрольную сумму файла с указанной на странице релиза:

```powershell
Get-FileHash HelixFillDNA-Setup-X.Y.Z.exe -Algorithm SHA256
```

> Почему установщик не подписан: сертификат для подписи кода стоит денег и
> требует проверки личности удостоверяющим центром. Для бесплатного
> проекта одного разработчика это пока не окупается. Исходный код открыт —
> любой желающий может прочитать его и собрать программу сам.

### Вариант 2 — из исходников

```bash
git clone https://github.com/Kirten-Po/HelixFillDNA.git
cd <repo>
pip install -r requirements.txt   # customtkinter, pyfaidx и др.
python gui/app.py                 # запуск GUI
```

> Список точных зависимостей приведён в `requirements.txt` проекта; в
> сборку (`HelixFillDNA.spec`) также включены бинарники `bcftools` /
> `tabix` / `bgzip` из папки `bin/`.

## Быстрый старт (CLI)

Приложение можно использовать и без графического интерфейса:

```bash
python main.py --csv ftdna.csv --template samples/template_v3.txt \
               --source ftdna --panel hrc --format v3 \
               --run-name ivanov --bin-dir bin
```

Обязательны только `--csv` (ваш файл) и `--template` (трафарет).
Полезные флаги: `--auto-detect-source` (определить источник по самому
файлу), `--rsq-threshold` (порог качества, по умолчанию 0.30),
`--normalize`, `--raw-chromosome-cache`, `--donors-dir`, `--output-dir`.
Полный список — `python main.py --help`.

## Как это работает «под капотом»

Коротко, по мотивам полного гайда (`Гайд_по_конвертации.docx`):

1. **Референсный геном** (GRCh37/human_g1k_v37) скачивается и
   индексируется один раз — он нужен, чтобы определить правильную
   ориентацию аллелей в каждой позиции.
2. Сырой файл источника чистится и превращается в отсортированный,
   проиндексированный **VCF**.
3. Сервер импутации требует не меньше 5 образцов в задании. Если своих
   тестов меньше, недостающие берутся из открытого проекта
   **1000 Genomes** (европейская популяция), обрезаются по позициям
   вашего чипа и объединяются с вашим VCF в общее задание.
4. Задание загружается на **Michigan Imputation Server** (панель
   HRC r1.1, GRCh37) — там недостающие позиции статистически
   восстанавливаются по референсной панели гаплотипов.
5. Итоговый файл собирается по «трафарету» — реальному экспорту
   23andMe (формата V3 или V5), который Генотек уже принимал: структура
   файла сохраняется один в один, а генотипы заполняются из
   импутированных данных, при этом ваши собственные измерения (там, где
   они есть) имеют приоритет как более точные. Искать трафарет самому не
   нужно — оба формата входят в установщик и лежат в папке `samples`.
6. Готовый файл в формате 23andMe появляется в папке `results` и готов к
   загрузке в Генотек.

Полная пошаговая инструкция — включая ручной прогон без приложения,
через WSL/Ubuntu и `bcftools` — доступна в `Гайд_по_конвертации.docx`.

## Конфиденциальность данных

Приложение не передаёт ваши генетические данные разработчику и не
хранит их за пределами вашего устройства. Загрузка на сервер импутации
выполняется напрямую с вашего компьютера под вашей учётной записью.
Подробнее — в `PRIVACY.md`.
