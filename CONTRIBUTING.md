# Как предложить исправление или улучшение

Спасибо за интерес к проекту! Исходный код HelixFillDNA распространяется
по лицензии [Apache License 2.0](LICENSE) — это касается и внешних
правок: присылая Pull Request, вы соглашаетесь, что ваш вклад
распространяется на тех же условиях (это стандартное правило для
проектов с лицензией Apache 2.0 — см. раздел 5 LICENSE).

## Порядок приёма правок

1. Сделайте форк репозитория и создайте отдельную ветку для своего
   изменения (не отправляйте PR прямо из `main`).
2. Опишите в Pull Request, что и зачем вы меняете — особенно если это
   не мелкая правка, а что-то влияющее на логику пайплайна
   (`main.py`, `core/`, `adapters/`).
3. **Все Pull Request перед принятием проверяются лично автором
   проекта** (Поломошнов Кирилл Сергеевич) — автоматического слияния
   нет. Это может занять время — пожалуйста, отнеситесь с пониманием,
   особенно к правкам, затрагивающим генетические данные или сетевые
   запросы (безопасность и корректность здесь особенно важны).
4. Если правка предполагает изменение поведения по умолчанию — по
   возможности добавьте тест в `tests/` (в проекте уже используется
   `pytest`).
5. После проверки и слияния ваш вклад остаётся зафиксирован в истории
   git (автор коммита/PR) — отдельный список контрибьюторов в проекте
   пока не ведётся, но история коммитов на GitHub сохраняет авторство
   постоянно.

## Что можно предлагать

- Исправления багов, в том числе в адаптерах форматов (FTDNA/MyHeritage/VCF).
- Улучшения документации (`README.md`, сайт в `docs/`).
- Новые тесты.
- Небольшие улучшения GUI (`gui/app.py`).

Крупные изменения архитектуры лучше сначала обсудить — откройте Issue
с описанием идеи, прежде чем тратить время на реализацию: так вы
не рискуете, что готовый PR не впишется в общий план проекта.
